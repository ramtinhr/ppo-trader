1. Mental model and system pipeline

OKX zips→ Rust tape→ scan .bin→ Go walk-forward→ simulate→ JSON / HTML

Rust = engine

Download archives, build the tick tape, scan millions of RSI × TP/SL combos, batch-simulate fills, optionally verify with NautilusTrader.

Go = product (dt)

Rank windows, run N/M walk-forward policy, serve browse HTTP, write reports. Changes compile in seconds without linking Nautilus.
Rule of thumb. Change fill rules in Rust (src/scan.rs + src/strategy.rs) and confirm with verify. Change how winners are picked in Go (internal/walkforward, internal/score).

3. End-to-end data flow

Research path (≈99% of compute)

  1. download fetches OKX daily trade zips into data/okx/BTC-USDT-SWAP/archives/ and verifies trade-ID continuity + volume vs OKX’s official 1D candle.
  2. Tape::load converts every trade into Nautilus L1 matching prices and builds a segment tree for TP/SL first_hit.
  3. scan --bucket window enumerates RSI pairs × timeframe × TP/SL × leverage into fixed-size window_*.bin files plus meta.json.
  4. Go dt walk-forward ranks those bins, picks finalists, batch-calls Rust simulate (JSONL) for closed trades, runs N/M score policy, writes JSON/HTML.

Truth path (slow)

Only the last / best combos go through Nautilus via verify, backtest, or window_nm_walk_forward --verify. Same fill rules as the scanner; disagreement fails the run.

6. On-disk formats

OKX archives

data/okx/BTC-USDT-SWAP/archives/
  BTC-USDT-SWAP-trades-2026-09-01.zip   # or gz
  (+ verified marker used by is_verified())

An archive day runs 16:00 UTC previous day → 16:00 UTC (same window as OKX’s official 1D candle).

Window scan (--bucket window)

  • meta.json — start/end, timeframes, lengths, TP/SL/leverage grids, window list, fees, size_btc, scan_version (1 = dense, 3 = staged)
  • window_*.bin — one 20-byte little-endian record per combo:
profit f32 | drop f32 | worst f32 | hold_hours f32 | trades u16 | wins u16
(window_score::RECORD = 20)

Month scan (--bucket month)

  • month_YYYY-MM.bin, all.bin — 12-byte LE records: sum f32 | drop f32 | trades u32

7. simulate JSONL protocol

Critical. Walk-forward must batch. Never spawn one process per combo.

Request line

{"id":"42","minutes":60,"fast":14,"slow":50,
 "exits":{"stop_pct":1.0,"targets":[[1.0,1.0]],"breakeven":false},
 "leverage":2,"logged":true,"record_fills":false}

Response line

Includes outcome (realized, fees, total, …), optional closed[] trades (exit_ms, entry_ms, net), optional fills[].

CLI flags: --start --end --config --data --size-btc --balance-usdt --jobs. Send {"flush":true} to force a batch flush.

9. Feature verify and the Nautilus boundary

Without --features verify (or with --no-default-features), backtest and strategy are not compiled and nautilus crates are not linked. Scanner rebuilds drop from painful LTO toward ~5–15s with the relfast profile. 
# Fast engine only
cargo build --profile relfast --no-default-features \
  --bin download --bin scan --bin simulate

# Need Nautilus
cargo build --profile relfast --features verify \
  --bin verify --bin backtest --bin window_nm_walk_forward

10. Config and safety

config/testnet.toml

  • risk.paper_only must be true (live rejected by validation)
  • risk.max_leverage validated (1–10 in config)
  • venues.okx.maker_fee_bps / taker_fee_bps

Secrets only in .env (gitignored). tv_check needs TradingView sessionid cookies. Never commit keys or seed phrases.

11. Standard research workflow

# 1) Two years of trades (end exclusive)
cargo run --release --bin download -- 2024-10-31 2026-10-31

# 2) Window scan
cargo run --release --bin scan -- --bucket window \
  --start 2025-10-01 --end 2026-10-01 --hours 24

# 3) Browse
./scripts/build_dt.sh
./dt browse --scan data/windowscan/<dir> --port 8091

# 4) Score walk-forward (Go)
./dt walk-forward --scan data/windowscan/<dir>

# 5) Price path (still Rust)
./dt price-walk --scan data/windowscan/<dir> --verify 0
